= NetApp Backup and Recovery 에서 KVM 워크로드를 알아보세요
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs:

[role="lead"]
NetApp Backup and Recovery에서 KVM 호스트와 가상 머신을 검색하여 보호 정책으로 보호할 수 있습니다. 검색하기 전에 KVM 환경은 Apache CloudStack 등의 관리 플랫폼에서 관리되어야 합니다.

*필수 NetApp Console 역할* 백업 및 복구 슈퍼 관리자. link:reference-roles.html["백업 및 복구 역할과 권한"]에 대해 알아보기. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["모든 서비스에 대한 NetApp Console 액세스 역할에 대해 알아보세요."^].

== 관리 플랫폼, KVM 호스트를 추가하고 리소스를 검색하세요.

관리 플랫폼 및 KVM 호스트 정보를 추가하면 NetApp Backup and Recovery 가 워크로드를 검색할 수 있습니다.


NOTE: 스토리지 시스템을 NetApp Console에 추가한 후에는 리소스를 검색하기 전에 몇 분 정도 기다리십시오. 스토리지 시스템을 추가한 직후에 리소스를 검색하면 검색이 실패할 수 있습니다.

.단계
. NetApp Console 메뉴에서 *보호* > *백업 및 복구*를 선택합니다.
. *워크로드*에서 *KVM* 타일을 선택하세요.
. *리소스 검색*을 선택하세요.
. 다음 정보를 입력하세요:
+
.. *작업 유형*: *KVM*을 선택하세요.
.. 아직 관리 플랫폼을 백업 및 복구와 통합하지 않았다면 *관리 플랫폼 추가*를 선택하십시오.
+
... 다음 정보를 입력하세요:
+
**** *관리 플랫폼 IP 주소 또는 FQDN*: 관리 플랫폼의 IP 주소 또는 FQDN을 입력하십시오.
**** *API 키*: API 요청 인증에 사용할 API 키를 입력하세요.
**** *비밀 키*: API 요청 인증에 사용할 비밀 키를 입력하세요.
**** *포트*: 백업 및 복구와 관리 플랫폼 간의 통신에 사용할 포트를 입력하십시오.
**** *에이전트*: 백업 및 복구와 관리 플랫폼 간의 통신을 원활하게 하기 위해 사용할 콘솔 에이전트를 선택하십시오.


... 완료되면 *추가*를 선택하세요.


.. *KVM 설정*: 다음을 수행합니다.
+
... 이 KVM 호스트에 대한 자격 증명을 아직 저장하지 않았다면 *자격 증명 추가*를 선택하십시오.
+
**** 이 호스트와 함께 사용할 콘솔 에이전트를 선택하세요.
**** 이 자격증의 이름을 입력하세요.
**** 계정의 사용자 이름과 비밀번호를 입력하세요.
**** *완료*를 선택하세요.


... 다음 정보를 입력하여 새 KVM 호스트를 추가하십시오.
+
**** *KVM FQDN 또는 IP 주소*: 호스트의 FQDN 또는 IP 주소를 입력하십시오.
**** *에이전트*: 백업 및 복구와 KVM 호스트 간의 통신에 사용할 콘솔 에이전트를 선택하십시오.
**** *자격 증명*: KVM 호스트에 사용할 저장된 자격 증명을 선택하십시오.




.. *고급 설정*: 선택적으로 KVM 호스트와 통신할 포트를 입력하고 목록에서 호스트의 관리 플랫폼을 선택할 수 있습니다.


. *발견*을 선택하세요.
+

TIP: 이 과정은 몇 분 정도 걸릴 수 있습니다.



.결과
KVM 작업 부하가 인벤토리 페이지의 작업 부하 목록에 표시됩니다.

== NetApp Backup and Recovery 보드로 계속

.단계
. NetApp Console 메뉴에서 *보호* > *백업 및 복구*를 선택합니다.
. KVM 워크로드 타일을 선택하십시오.
. 백업 및 복구 메뉴에서 *대시보드*를 선택합니다.
. 데이터 보호 상태를 검토하세요.  위험에 처한 작업이나 보호된 작업의 수는 새로 발견, 보호 및 백업된 작업 부하에 따라 증가합니다.
